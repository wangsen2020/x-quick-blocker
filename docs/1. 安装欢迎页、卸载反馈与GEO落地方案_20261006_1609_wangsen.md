# X Blocker 落地「安装欢迎页 + 卸载反馈 + GEO」方案

对照 [xdown 的复用手册](../../x-media-downloader/docs/5.%20安装欢迎页、卸载反馈与GEO复用手册_20261006_1449_wangsen.md)，
把已在 xdown 上线验证的三件事搬到 X Blocker（扩展 `x-quick-blocker` + 子站 `xblocker-website`）。

手册本身已经是方案，这份文档只回答一个问题：**xblocker 这边和手册的假设有哪些不一样，因此要多做什么。**
按手册最后一条「先写方案再动手」，先给你核实。

---

## 零、核对结果：手册的四个假设在 xblocker 这边不成立

手册写「下面的文件基本可以直接拷贝」，前提是三个扩展结构相同。实际核对后有四处不同，都要额外做：

| # | 差异 | 影响 |
| --- | --- | --- |
| 1 | **扩展完全没有 background service worker。** `manifest.json` 里没有 `background` 字段，整个扩展只有 content script（`src/inject.js` + `src/content.js`）和 popup。 | 欢迎页和卸载 URL 都挂在 worker 上。要新建 `src/background.js`，并在 manifest 加 `"background": { "service_worker": "src/background.js", "type": "module" }`。**不增加任何权限**（`tabs.create`、`setUninstallURL` 都不需要）。 |
| 2 | **没有 `package.json`，也没有 `test/` 目录。** | 手册说「参考 `test/site.test.js`」，但这边没有测试基建。要加 `package.json`（`"type": "module"`、`"test": "node --test"`、`lint` 脚本 `node --check`），测试才能跑。 |
| 3 | **没有 `CHANGELOG.md`。** | 手册说「README 与 CHANGELOG 各加一条」。这边只有 README。建议这次顺便建 CHANGELOG，从 0.4.x 起记。 |
| 4 | **子站缺的不只是欢迎页和卸载页。** xblocker-website 是在 xdown 做 GEO 之前克隆的，GEO 那一整批（手册 §5）一项都没有。 | 除 `welcome.vue` / `uninstall.vue` / `functions/` 外，还要补 `about.vue`、`llms.txt`、首页 `@graph`（Organization + WebSite + sameAs + dateModified）、facts 事实区、byline 署名、citations 引用、footer `h4`→`h2`、`BlogPost.vue` 的 author/publisher/date。i18n 要新增 `about` / `feedback` / `welcome` 三个顶层组和 `home.byline` / `home.citations` / `home.citeTos` / `home.citePolicies` / `home.citeMit` / `home.facts` / `home.source` 七个键，**4 种语言各一遍**。 |

顺带两个核对出来的小结论：

- 手册 §3.5 说「`wrangler.local.toml` 不要提交」，但 xdown-website 里它其实是**已提交**的，内容只有本地占位 database_id，没有密钥。保持提交即可，这条可以从手册里划掉。
- 手册 §4 的「兜底值写死 `'xmd'`」确认存在，拷过来要改成 `'xbl'`。

## 一、扩展端（`x-quick-blocker`）

1. **新建 `src/lib/site.js`** —— 照抄 xdown，只改两处：`SITE = 'https://xblocker.goodexts.com'`，`ext: 'xbl'`。纯函数，语言前缀映射 `zh*→/zh`、`pt*→/pt-br`、`es*→/es`、其余空。
   扩展有 8 种界面语言（en / zh_CN / zh_TW / ja / ko / es / pt_BR / id），子站只有 4 种，所以 ja / ko / id 一律落英文页 —— 这是手册规定的行为，测试里要断言。
2. **新建 `src/background.js`** —— worker 启动时 `setUninstallUrl()`；`onInstalled` 里 `reason === 'install'` 时存 `installedDate`（YYYY-MM-DD）再开欢迎页，`install` 和 `update` 都重设卸载 URL。整个 worker 只做这件事，失败只 `console.warn`，不抛。
3. **manifest** —— 加 `background` 字段，bump 版本号到 **0.5.0**（新功能，不是修补）。
4. **新建 `package.json` + `test/site.test.js` + `test/site-lifecycle.test.js`** —— 覆盖：语言前缀映射（含 ja/ko/id 落英文）、URL 参数顺序与取值、URL 里**没有**多余字段和用户标识、长度 < 1023、install 只开一次欢迎页、update 不开、`setUninstallURL` 抛错不影响 worker。
5. **`PRIVACY.md`** —— 加一节：卸载时打开的页面带哪些参数（版本、界面语言、安装日期、固定 utm），不带任何用户标识；反馈是用户自愿提交的。
6. **`README.md` + 新建 `CHANGELOG.md`** —— 各加一条。

## 二、子站（`xblocker-website`）

| 文件 | 做法 |
| --- | --- |
| `app/pages/uninstall.vue` | 拷贝 xdown 版，改推广位：推 **xdown + xexport**（xdown 站推的是 xblocker + xexport）。两种模式、详情必填规则、选填联系方式、X 私信复选框、honeypot、提交后 `scrollIntoView`、手机端 `display:contents` 换序，全部保留。`noindex`。 |

| `functions/api/uninstall-feedback.ts` + `schema.sql` | 直接拷贝，只把 Telegram 前缀兜底 `'xmd'` 改成 `'xbl'`。 |

| `app/pages/index.vue` | `@graph` 补 Organization + WebSite + `sameAs` + `dateModified`；加 facts 事实区、byline 署名、citations 引用（X 服务条款 / CWS 政策 / MIT 原文）。 |

| `nuxt.config.ts` | `prerender.routes` 加 `/welcome` `/uninstall` 及 zh / pt-br / es 版本；`typescript` 排除 `functions/`。 |

| 隐私政策页 | 4 语言各加「卸载反馈」一节。 |
| `README.md` | 加一节说明反馈数据流。 |

## 三、Cloudflare（这一步要你动手）

数据库 `goodexts-feedback` 和表都已建好，三个扩展共用 `ext` 列区分，**不用再建库建表**。在 xblocker-website 的 Pages 项目里：

1. Settings → Bindings → Add → D1 database，Variable name `DB`，选 `goodexts-feedback`。
2. Variables and secrets：Text `TG_CHAT_ID` = `5115045923`；Secret `TG_BOT_TOKEN`。
3. **token 必须你本人粘贴** —— 我把对话框开好、选好 Secret、填好变量名，然后用 `bsk request-help` 把控制权交给你。我不往任何输入框里填 token。
4. 绑定只在**下一次部署**后生效：先配好，再推代码。

手册还提醒：现在用的仍是聊天里出现过的旧 token，等你在 @BotFather `/revoke` 换新的之后，三个项目都要更新并各重新部署一次。

上线后验证：线上提交一条 `LIVE TEST` → D1 Console `SELECT` 确认入库 → Telegram 确认收到 → `DELETE` 掉测试行。

## 四、主站 goodexts.com 同步

xblocker 的卖点（手册 §6 已定，且与 xdown 的 Premium 卖点不同，不照搬）：

> **X 原生只能一个一个屏蔽**：Block 埋在 ⋯ 菜单里要点三次，而且它不帮你找该屏蔽的账号。本扩展按关键词或正则把账号找出来，你确认后批量屏蔽。

写进：子站 FAQ 新增一问（同时进 FAQPage schema）、「Why use」导语、事实区、`llms.txt` 摘要、主站 `i18n/locales/*.json` 的 `ext.xblocker` 卡片描述、主站 `app/content/home-about/*.vue`。4 语言都改。
用具体场景讲清楚，不堆关键词。

**商店描述这次不改** —— 改 listing 会触发重新审核，等当前版本过审后再说。

## 五、顺手修（建议同一个版本一起发）

核对代码时发现两个与本次无关、但既然要发版就该一起修的问题：

1. **FAB 悬停提示是硬编码中文。** `src/content.js:1023` 写死 `title: 'X Quick Blocker（拖动可移动位置）'`，所有非中文用户悬停都看到中文。应走 `chrome.i18n.getMessage`，8 种语言都补键。
2. **面板标题是内部名。** `src/content.js:1099` 写死 `'X Quick Blocker'`，商店名早已改成 `X Blocker`。这个之前就提过，一直压着因为要发新版 —— 这次正好发。而且**欢迎页截图里会露出这个标题**，不改的话截图和商店名对不上。

## 六、要你拍板的四件事

1. **版本号 0.5.0 可以吗？** 加了 background worker 和新功能，按语义化应该是 minor。
2. **0.4.3 在商店是什么状态？** 如果还在审核中，就等它过了再提 0.5.0，别排队顶掉。
3. **第五节那两个修，一起发还是单独发？** 我建议一起，理由是欢迎页截图依赖面板标题。
4. **CWS listing 名称要不要改成以新主词开头？**（上次遗留的问题，和本次独立，可以先放着。）

## 七、顺序

扩展端和子站可以并行，但**子站要先上线**，否则新装用户点开欢迎页是 404：

1. 子站：页面 + API + GEO + i18n + 图 → 本地 `NITRO_PRESET=static pnpm generate` 通过 → 本地 wrangler 联调反馈链路
2. Cloudflare：配 D1 绑定 + 变量（你粘 token）
3. 推子站 → 自动部署 → 线上 `LIVE TEST` 验证三处
4. 扩展端：site.js + background.js + manifest + 测试 + 文档 → bump → 打包
5. 主站 goodexts.com 同步
6. 商店上传（**提交前必须你明确确认**）

## 八、沿用的红线

- 对外发布（发帖、提交第三方表单、授权 OAuth）前先问你。
- 商店三个认证勾选框和最终 Submit 按钮永远不自己点。
- token、密码不碰，要你自己输。
- locale JSON 用字符串替换改，不要 `json.dump` 整文件重写（zh/pt-br/es 是紧凑格式，en 是 indent=2）。
- 截图涉及隐私的地方用 8–10px 像素块轻码。
